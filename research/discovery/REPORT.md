## 1. Ways to discover hosts from the server host

Start with local, read-only sources. Treat every source as a lead, deduplicate by stable host identity/address, preserve source provenance, and represent SSH as separate evidence. “Peer exists”, “SSH is enabled by policy”, “an SSH service responds”, “host key is trusted”, and “this user can authenticate” are different states.

| Source | What it yields | SSH acceptance evidence | Privacy | Cost and failure modes |
| --- | --- | --- | --- | --- |
| NetBird local daemon: `netbird status --detail --json` | Mesh peer names/IDs, overlay addresses, OS/version and current connection data; JSON/detail flags are documented by the CLI. | Peer `ssh_enabled` / server-side SSH allowance are configuration hints. They do not prove current-user authentication. NetBird SSH is disabled by default and requires server setup and policy. | High: users, addresses and topology. Show matched peer and SSH hint; keep the full peer graph hidden. | Low local daemon IPC. Missing/stopped daemon, stale peer view, schema drift, DNS failure or access policy can make results incomplete. Do not query cloud APIs by default. [NetBird CLI](https://docs.netbird.io/get-started/cli), [NetBird SSH](https://docs.netbird.io/manage/peers/ssh), [peer fields](https://docs.netbird.io/api/resources/peers) |
| Tailscale local daemon: `tailscale status --json` | Tailnet peers, names, addresses and local state. The detailed JSON schema is subject to change. | Status does not establish Tailscale SSH policy or a successful login. The documented JSON does not promise a stable peer SSH-host-key field; Tailscale SSH validates host identity during the SSH connection and applies policy. Treat version-specific host-key metadata as an identity hint, not login acceptance. | Very high: tailnet identity, address and topology. Aggregate by default. | Low local daemon IPC; can be stale or unavailable. Pin parsers to supported client versions and fail closed on unknown shapes. Return a match boolean/source, not raw records or keys. | Low local lookup per candidate. Unknown hashed names, key rotation/revocation, aliases and alternate known-host files limit matching. [OpenSSH `sshd(8)`](https://man7.org/linux/man-pages/man8/sshd.8.html), [OpenSSH `ssh-keygen(1)`](https://man7.org/linux/man-pages/man1/ssh-keygen.1.html) |
| `~/.ssh/config` and `Include` files | Host aliases, hostnames, ports, usernames, `ProxyJump`, and identity-file paths. | No. `Match` and order-sensitive directives alter effective values. [OpenSSH `ssh_config(5)`](https://man7.org/linux/man-pages/man5/ssh_config.5.html) |
| `/etc/hosts` | Static local address and hostname aliases. | None. It does not establish liveness or an SSH service. | Medium: internal names and IPs. | Very low local read. Entries may be stale; NSS resolution order can differ. [hosts(5)](https://man7.org/linux/man-pages/man5/hosts.5.html) |
| Neighbor table: `ip neigh show` | Cached IP-to-link-layer bindings and neighbor state for recently seen same-link devices. | None. Do not send probes or refresh the cache as part of quiet discovery. | High: local network topology and MAC addresses. | Very low kernel query. Cache ages out; it only covers a link and misses sleeping or never-contacted hosts. [ip-neighbour(8)](https://man7.org/linux/man-pages/man8/ip-neighbour.8.html) |
| mDNS/Bonjour: `_ssh._tcp` browse | Service instance/name and advertised address for hosts announcing SSH. [Avahi browse](https://linux.die.net/man/1/avahi-browse), [Apple Bonjour example](https://developer.apple.com/forums/thread/735862) |
| Proxmox: `pvesh get /nodes --output-format json` | Nodes in the local Proxmox cluster through its API. | None; membership is not SSH acceptance. | Very high: cluster node names and status. | Low-medium local API call; requires suitable API permission and a working cluster/API. Do not enumerate guests by default. [Proxmox VE Administration Guide](https://pve.proxmox.com/pve-docs/pve-admin-guide.pdf) |
| Docker contexts: `docker context ls` | Locally configured context names, current context and endpoint hints. | None. Endpoint may be a local socket, remote SSH/TCP, stale or unreachable. | High: endpoint hostnames and user paths. | Low local config read. Do not use `context inspect` to surface full endpoints unless opted in. [Docker context ls](https://docs.docker.com/reference/cli/docker/context/ls/) |
| Kubernetes: `kubectl config get-contexts -o name` | Context names from local kubeconfig; it does not contact a cluster. | None. | Very high: environment names; kubeconfig files may contain credentials. Read names only and never emit tokens, certificates or raw files. | Low file parse. Multiple `KUBECONFIG` files, malformed config and stale contexts can mislead. [kubectl config get-contexts](https://kubernetes.io/docs/reference/kubectl/generated/kubectl_config/kubectl_config_get-contexts/) |
| libvirt: `virsh -c qemu:///system list --all` | Local hypervisor domains. | None. | High: VM names and state. | Low-medium daemon IPC; permissions and daemon state vary. Use explicit local URI; do not query remote libvirt endpoints. [virsh(1)](https://www.libvirt.org/manpages/virsh.html) |
| Cloud CLI files or APIs | Could expose configured accounts, profiles, regions, endpoints and credentials. | None. | Very high; files may contain reusable secrets. | Do not scan or call cloud APIs by default. IMDS may return instance identity and managed-identity/temporary credentials; a link-local request is still a metadata access. Use local DMI/device-tree/hypervisor hints only. [AWS IMDS](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/configuring-instance-metadata-service.html), [Azure IMDS](https://learn.microsoft.com/en-us/azure/virtual-machines/instance-metadata-service) |

For D141/D144, keep read-only local sources on by default with a switch per source, refresh when a mesh changes, and avoid idle polling. If the owner retains D144’s active fallback, use one rate-limited unauthenticated TCP connect and optional short banner read on port 22 or the configured NetBird SSH route. NetBird documents port 22 being routed internally to 22022 for its SSH service; use the configured route because deployments can differ. Never authenticate during discovery. Show `service responds`, `no listener`, `blocked`, or `unknown`; a timeout cannot distinguish host-down, route, firewall or policy, and a banner cannot prove user access or trusted identity. This active check is distinct from passive local source collection.

### Shell-agnostic first sniff

A candidate single SSH command is:

```sh
echo %OS% %PROCESSOR_ARCHITECTURE% $env:OS $env:PROCESSOR_ARCHITECTURE; uname -sm; cat /etc/os-release
```

The shell leaves distinct markers: `cmd.exe` expands `%OS%` and `%PROCESSOR_ARCHITECTURE%` and treats semicolons as text after `echo`; PowerShell leaves the percent tokens literal and expands `$env:` variables; POSIX leaves percent tokens literal, prints the unset `$env` portions as `:OS`/`:PROCESSOR_ARCHITECTURE`, then runs `uname` and reads `os-release`. On Windows, the later POSIX commands may emit bounded “not found” errors; cap both streams and accept only the marker fields. On Linux, parse the `ID` and `ID_LIKE` fields from the file output. This candidate avoids writes and network calls.

This is a researched candidate, not a validated cross-shell contract: no Windows host was available to verify cmd, Windows PowerShell 5.1 and PowerShell 7 quoting/output. The parser must reject ambiguous/truncated output and return `unknown`; validate the command on those shells before implementation. Check Linux `os-release` markers after identifying POSIX. Do not trust a single environment variable as a distro identity.

Parsing notes cover stale/unknown, locale, version variation, container boundaries and redaction. A missing command maps to unsupported/unknown, never a negative fact.

Additional platform notes that affect parsing:

- Windows uses selected CIM properties for machine facts, `Get-NetTCPConnection -State Listen` for listeners, and the Windows Time/firewall APIs for local status. “Load” is a processor-load sample, not Unix load average. Convert CIM memory units and sum logical CPUs across processors. OpenSSH’s shell registry value must be checked before choosing a PowerShell collector. [Microsoft CIM examples](https://learn.microsoft.com/en-us/powershell/scripting/samples/collecting-information-about-computers), [listener API](https://learn.microsoft.com/en-us/powershell/module/nettcpip/get-nettcpconnection?view=windowsserver2025-ps)
- macOS uses `sw_vers`, `sysctl`, `getifaddrs` and IOKit; `system_profiler` is the slower opt-in fallback. `softwareupdate --list` may contact Apple and is not a default cached query. `socketfilterfw --getglobalstate` reports the Application Firewall, not the complete PF ruleset. Intel vs Apple silicon and Rosetta process translation must not be collapsed into one architecture value.
- Linux update checks are package-manager-specific. The matrix avoids refresh flags. Image-based systems report local staged deployment status, not available updates. OpenWrt 25.12 switches to `apk`; the documented package instructions warn against blindly applying package upgrades to firmware devices. [OpenWrt 25.12 release notes](https://openwrt.org/releases/25.12/notes-25.12.0)
- BSD and appliance commands are platform-specific fallbacks, not a promise that all utilities are installed. TrueNAS, pfSense and OPNsense should expose an appliance API only after an owner-approved scope and permission model.

## 5. One-shot probe and refresh proposal

Following D145, the collector should be a native-first Rust infraternal agent binary in a no-install, one-shot `--probe-once` mode. The SSH step sends a tiny shell/OS/architecture sniff and then streams or invokes the matching signed infraternal agent binary through the same SSH connection, returning one bounded JSON document and exiting. It must not install, enroll, create state or alter host configuration. The owner still needs to decide how a matching binary is supplied transiently (for example, a platform-specific stdin transfer or a remote executable path that is cleaned up); that mechanism is not selected here.

The native collector should use `/proc`, `/sys`, `getifaddrs`, `sysctl`, CIM and OS APIs first. External commands are fallbacks with a fixed worker limit, per-command timeout, output cap, total deadline, process-group termination and reaping. Each fact carries `ok`, `unsupported`, `permission_denied`, `timeout`, `truncated`, `stale` or `error`; include a timestamp, duration, source, confidence and typed value. Do not return raw command output. No passwordless-sudo check, privilege escalation or root request is part of discovery. The matrix’s 500 ms native group, 750 ms command, 3 s slow opt-in and 5 s total limits are **candidate ceilings**, not measured budgets; scale them against the perf VM and realistic host counts before adoption.

D126’s split remains useful for refresh behavior:

- **Static facts:** OS/version, kernel, architecture, model, CPU, init, virtualization, package managers and infraternal agent mode at enrollment/upgrade or an explicit refresh.
- **Live facts:** uptime, load, memory/disk capacity and engine reachability only while the Machine view is open; stop polling when it closes.
- **Sensitive or expensive facts:** explicit opt-in and sampled on demand. Update status uses existing local caches; SMART, firewall detail, cloud identity, mesh peer records, listeners and SSH settings are not default live polls.
- **No installed infraternal agent:** the server has only its latest snapshot. It cannot refresh host facts without a new user-authorized SSH probe or an enabled discovery integration.

No probe wall-time, JSON size, per-fact timeout, CPU, RSS or scale measurement is available because every host attempt stopped before remote execution. The local connection failure numbers above must not be used as a collector performance benchmark. The scale budget remains per host × expected host count, and the expected deployment count must be set before a scale measurement.

## 7. Review checklist and limits

- D126 facts/defaults and optional fields are listed; all extra facts are opt-in pending owner direction.
