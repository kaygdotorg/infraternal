Priming lifecycle review found a connection-wide mode race: the client switches future writer selection to ordinary before the server processes activation, while an already-started setup may still deliver its binding. That setup could evict the active ordinary shim peer. Additive proposal under negotiated REMOTE_PRIMED_WRITERS bit 5: a primed native writer begins with canonical Call(0, transport.prime, {}) followed by AttachTerm on the same ordered bound stream; ordinary writers begin with AttachTerm. The receiver uses per-stream intent, including setup arriving across promotion; no global mode toggle. The marker is exactly {} (no additional JSON parser). Existing peers/ordinary streams retain their greeting and first-frame contract. Pending setup tasks are cancelled/joined before server promotion; retained input and authority remain unchanged. A real-QUIC marker regression is being established before implementation, with the concurrent-promotion server regression to follow.
