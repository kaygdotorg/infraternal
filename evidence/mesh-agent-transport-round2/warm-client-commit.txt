Keep an enrolled fallback warm while the mesh transport is active (#129)

After the mesh server advertises standby support, independently prove and
park an enrolled fallback, retaining its control decoder and server Hello.
A silent mesh interruption promotes that authenticated link without a new
TLS handshake; failed warm probes leave the live mesh untouched. Background
mesh probes continue alongside fallback and restore preference on success.
The mesh session uses the remote plugin's current-RTT authenticated guard.

Preparing work is allocated only on a mesh link; component-off fallback
owns no warming future. Both session futures leave scope before retiring
the old channel, preserving cancellation and partial-frame invariants.
Legacy peers retain their existing dial path. A second active dispatcher
was rejected because it would replace the live host/terminal before failure;
a fixed2s loss deadline and cold reconnect were rejected for latency.
