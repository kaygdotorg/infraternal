# Author review

- Compact updates require an explicit strict identity probe; ordinary identity replies retain exactly the two legacy fields. Strict older nodes reject the probe and are retried with the ordinary request. Existing lifecycle tests exercise that fallback; older identities use the original bounded chunks. Full snapshots, identity changes and large fragmented edits retain the original encoder. Rejected deltas trigger a full snapshot.
- Ranges select existing ordered entries, never expand numeric identifiers. Entire ranges are validated before mutation. Missing endpoints, overlaps, wrong identity, stale bases and snapshot/range mixtures refuse. Null preserves one direction. Grouping never crosses a protected unchanged peer.
- Parsing retains the existing action byte budget, unknown-field and duplicate-field refusal. Nested ranges require objects; positional arrays refuse. The existing exact parser fuzz target includes valid compact and malformed seeds.
- Node application retains inventory validation, journal fsync, rollback, recovery and exact connection-state cleanup. New rules refuse established disallowed traffic before cleanup; permitted state remains intact.
- The compatibility optimization retains owned raw guards only when addresses and aliases are unchanged after successful adoption. It renders full replacement filter tables. Only a verified removal of permissions after complete owned installation can omit duplicate frontend syntax preflight; actual full transactions still validate. Changed bindings, peer identities, addresses, concrete permissions, aliases, incomplete ownership or either fence keep both preflights. Eligibility regressions and failed-journal rollback/recovery cover the boundary. Initial install, changed addresses/aliases and rollback use both tables. Mutations remain serial: the measured parallel experiment was worse.
- Diagnostics require an optional feature and an explicit environment flag. Shipping builds retain neither timers nor logger. Refusal timestamps are returned only with successful completed application; packet assertions compare sent timestamps against final kernel installation. Durable completion remains independently recorded.
- Auth reproduction uses an immutable dev export and 200 repetitions without generated host load. The inventory fixture controls its clock; production deadlines and explicit deadline tests are unchanged. Other gate failures require the documented baseline comparison and cannot be waived by an isolated passing rerun.
- No engine, migration, background worker or runtime dependency was chosen. Existing clock support is enabled only by optional diagnostics. Scope remains in the removable mesh plugin and test harnesses. No deployment, host fixture changes or issue closure.
- Performance scope is explicit: 1,000 installed peer keys on each of three real nodes, two live traffic receivers and three control workers. This does not claim 1,000 simultaneously connected coordinator workers. Only the locked perf VM supplies performance numbers. Baseline diagnostics are recorded as a patch.
