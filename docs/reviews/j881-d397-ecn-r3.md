## Contract and source audit

There is no flow-key table. Every authenticated eligible frame spends credit,
even when no congestion signal is due. Eligibility uses authenticated
plaintext length before IP trimming, clamped to at least the validated packet
length. A frame above 256 bytes neither consumes nor receives small-packet
credit. The full padded length of an eligible frame is charged.

`SparseBudget` stores credit as byte-nanoseconds. For elapsed time T within an
above-target episode, exempt eligible bytes cannot exceed
`65536 + T * 32768 / 10000000` (T in nanoseconds). Refill is continuous, capped
at 65536 bytes, and independent of delivered congestion signals. Saturating
multiplication/addition handles arbitrary time gaps; nondecreasing refill time
prevents a backwards clock from duplicating credit. The cost multiplication
is reached only for lengths at most 256, so it cannot overflow. A rejected
small packet does not incur debt: with a continuous timebase, after overload stops, 20 ms restores all
credit. Four deferred congestion signals is the maximum.

`PeerState` owns each controller. The state is constant in flow count, with
no allocation in the budget; counters shared across peers are telemetry only.
Peers share the underlying socket/CPU, so isolated accounting is not a claim
of a fair packet scheduler or protection against arbitrary host CPU overload.
Within a peer, small streams share the approved aggregate envelope; a small
flood can consume another small stream's credit on that same peer.

This controller is not a hard queue-length cap. Small traffic inside the
approved envelope deliberately passes even at high observed sojourn. Future
or more-than-one-second receive ages deliberately pass and reset the episode;
exactly one second remains judged. A real queue exceeding that ceiling is
indistinguishable from a realtime clock discontinuity under this contract.
Unknown zero stamps pass without changing the controller. No claim of
monotonic clock provenance or full tunnel ECN propagation is made.

The receive wrapper snapshots the socket's timestamps and compacts them with
the retained datagrams. The fork reads those stamps before packet parsing,
keeps them aligned with completion slots, and judges only authenticated,
source-authorized IP packets. Authenticated length is captured before IP
length validation trims padding. With `GOTATUN_AQM=off`, the public judgement
path, receive timestamp collection, and telemetry startup are bypassed.
The user documentation explicitly says macOS AQM stays off because no kernel
receive timestamps reach that path.

## P1: ordinary idle/resume drops the complete new initial window

This case requires no clock discontinuity. The virtual clock progresses
normally through one idle hour with no arrivals. After priming one controller,
the test resumes ten 1,400-byte Not-ECT packets at 10 us spacing. All stamps
are fresh, all ages are 3 ms, and the complete burst lasts only 90 us.
The same current samples are also sent to a fresh controller.

```text
J881 ordinary idle hour: warm_drops=10/10 fresh_drops=0/10 valid_age_ms=3 burst_us=90
```

The warm controller drops the whole resumed initial window before the new
burst has existed for the 10 ms observation interval. This is normal traffic
history, independent of the P2 host-clock condition. The positive one-hour
trace in the next section can likewise represent ordinary elapsed idle time.
The source retains `signalling`, `first_above_ns`, and old signal deadlines
when no packet arrives; the engine's idle path releases buffers but supplies
no controller episode reset. Only a later below-target/invalid-age sample
clears that history. A newly delayed burst need not contain either sample.

The actual-library assertion fails on the rebased pin. Receipt:
`final-regressions0103.log`, three passing checks and three expected failures.
This newly confirmed P1 applies the user's final-round stop rule. Both full
fast attempts were stopped by their exact recorded process groups; there is
no final green-gate claim and no further implementation patch in this job.

## P2: fresh post-step receive stamps retain stale controller deadlines

The controller passes the original stale-stamp checks, but a clock step can
leave every new receive age valid. The regression primes the controller, then
offers 100,000 packets with 1,400 inner bytes each at 10 us dequeue spacing.
Their fresh timestamps describe a growing queue: receive ages rise from
3 to 103 ms, entirely inside the accepted one-second ceiling.

| Time change | Not-ECT signals | ECT signals |
| --- | ---: | ---: |
| Stable-clock control | 3,523 / 100,000 | 3,523 / 100,000 |
| One hour backwards | 0 / 100,000 | 0 / 100,000 |
| One hour forwards | 100,000 / 100,000 dropped | 100,000 / 100,000 marked |

The backward case leaves 140 MB of inner data unmarked while observed delay
grows. `judge_frame_with` accepts `now - rx`, so it never clears the old
`first_above_ns` or `signal_next_ns` realtime deadlines. Backward time leaves
the first deadline in the future; forward time repeatedly catches up the old
signal schedule. The forward trace also represents an idle gap followed by a
burst whose first sample is already above target.

Both original and rebased fork libraries fail the new assertion (exit 101),
with stable-clock controls passing. The production host clock was unchanged;
this is a deterministic controller-seam trace. Receipts are `clock-fresh.log`
and `clock0103-fresh.log`. Repair the controller's time and idle-episode
handling while retaining the approved byte envelope; measure the cost of any
additional clock read. The aggregate-budget evidence does not call for another
accounting redesign.

## Required design follow-up

Keep the constant per-peer small-packet bucket and its approved B/I/S values.
The controller's episode interface must change before another implementation
is proposed. A monotonic clock alone does not fix an ordinary elapsed idle gap.

1. Define the protected queue and its dequeue point across kernel receive,
   crypto/order and TUN handoff. Specify how empty/idle is observed. A missing
   callback alone cannot prove drain: CPU stalls can leave a backlog growing.
2. Put duration deadlines and refill on a monotonic timeline, retaining the
   separate realtime receive-age validation. Define episode invalidation for
   both fresh and stale stamps across clock steps.
3. Expire old above-target evidence after a genuine idle/empty episode. Rearm
   the observation interval and prevent old deadlines from becoming a catch-up
   burst. Preserve peer isolation, bounded owed signals and the existing
   credit conservation/recovery contract.
4. Specify and test resumed bursts around the observation/refill boundaries
   (including 20 ms, 200 ms and long idle), CPU/peer-lock/TUN stalls, fresh and
   stale clock transitions, mixed sizes, padding and both ECN capabilities.
   Include an engine-level receipt with real UDP timestamps and controlled
   backpressure, alongside the deterministic controller checks.
5. Measure clock-read/hot-path cost and controller bytes per peer times the
   expected peer count. Reuse the retained J878 baseline; no new library or
   controller engine was selected in this review. Bring that concrete contract
   and measured candidate to the owner, rather than another special-case fix.

The P3 conversion fix should use checked arithmetic with the current fallback.
The four Mac coordinator-test portability failures are a separate follow-up.
